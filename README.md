# S.M.T Messages — גרסה 2

מערכת ניהול SMS מתקדמת מעל **ימות המשיח**, שרצה כולה על **Cloudflare Workers + D1**.

V2 נבנתה מחדש מהיסוד על בסיס הגרסה הקודמת. העיקרון המרכזי: **הדפדפן לא מקבל אף פעם את הטוקן של ימות המשיח**. כל הקריאות יוצאות מהשרת.

V2 יושבת על **אותו מסד D1** כמו הגרסה הישנה ולא מפריעה לה:

- כל הטבלאות החדשות מתחילות ב-`v2_`.
- טבלת המיגרציות נפרדת (`v2_migrations`).
- Worker נפרד (`sms-v2`).
- מהטבלאות הישנות V2 רק **קוראת**: בתצוגת "הגרסה הישנה" בפאנל הניהול, ובייבוא מערכות לפי קוד אישי ישן.

## מה יש בפנים

### אבטחה

- **הטוקן נשאר בשרת.** הטוקן והסיסמה של כל מערכת מוצפנים ב-AES-256-GCM במסד, ולא חוזרים לדפדפן גם לא לבעל החשבון.
- **התחברות מחדש אוטומטית.** כשהמערכת מחוברת בסיסמה והטוקן פג, השרת מתחבר מחדש בעצמו.
- **אימות דו-שלבי של ימות המשיח.** יש זיהוי, קישור לאימות, ובדיקה חוזרת אוטומטית עד שהאימות מושלם.
- **סיסמאות.** נשמרות כ-PBKDF2-SHA256 (100,000 איטרציות).
- **סשנים.** עוגיית `HttpOnly`, ובמסד נשמר רק ה-SHA-256 של הטוקן.
- **הגנה מבקשות זדוניות.** כל בקשה שמשנה מצב חייבת כותרת מיוחדת (הגנת CSRF), ויש CSP קשיח.
- **הגבלת קצב** על כניסה, הרשמה, שליחה ו-API.
- **יומן ביקורת** לכל פעולה רגישה.

### הרשמה חכמה

- **חשבון אחד לכל מייל.** `moshe.cohen@gmail.com`, `MosheCohen+x@googlemail.com` ו-`moshecohen@gmail.com` נחשבים לאותה כתובת.
- **אימות מייל.** קוד בן 6 ספרות שנשמר מגובב, עם 5 ניסיונות, תוקף של 15 דקות והמתנה של דקה בין שליחות חוזרות.
- **חסימות.** מיילים זמניים (mailinator ודומיהם) נחסמים, ויש הגבלה על מספר החשבונות מאותה כתובת IP ביום.
- **הצעת תיקון** לשגיאות כתיב בכתובת (`gmial.com` ← `gmail.com`).
- **שלושה מצבי הרשמה:** פתוחה, באישור מנהל, או סגורה.
- **מיילים מעוצבים בעברית:** קוד אימות, ברוך הבא, אישור חשבון, איפוס סיסמה, התראה על כניסה מכתובת חדשה, והעברת SMS.

### למשתמש

- **הודעות.** תיבה עם שיחות, ספירת "לא נקרא", הצמדה, ארכיון ומועדפים. השליחה מופיעה מיד על המסך עוד לפני אישור השרת. יש סטטוס מסירה וייצוא ל-CSV.
- **אנשי קשר וקבוצות.** ייבוא CSV עם זיהוי אוטומטי של עמודות (גם בעברית), חסימת מספרים (מוסתרים מהתיבה ולא מועברים באוטומציות) והערות פנימיות.
- **שליחה וקמפיינים.** שליחה לקבוצות ולרשימות, התאמה אישית עם `{name}` ו-`{first}`, תזמון, תור שליחה ברקע עם מעקב התקדמות, תבניות והיסטוריה.
- **אוטומציות** שרצות בשרת גם כשהדפדפן סגור:
  - **SMS למייל לפי ימים ושעות**, כולל חלון שחוצה חצות. הודעות שמגיעות מחוץ לשעות אפשר **לשמור** ולשלוח כשהחלון נפתח, או **לדלג** עליהן. שליחה מיידית או כסיכום כל X דקות. סינון לפי מילה או שולח.
  - **מענה אוטומטי** עם הגבלה: פעם ב-X שעות לכל שולח.
  - **Webhook** חתום ב-HMAC-SHA256.
- **מערכות.** חיבור עם מספר וסיסמה או עם טוקן קבוע, צבע לכל מערכת, ומעבר בין מערכות. **ייבוא בלחיצה מהגרסה הישנה** לפי הקוד האישי.
- **גישת אורחים.** מחליפה את "הקודים הזמניים". לכל קוד מגדירים הרשאות (צפייה ו/או שליחה), מספרים מותרים, מכסת שליחות ותוקף. הקוד מוצג פעם אחת בלבד, ואפשר להאריך, לחדש ולבטל.
- **API למפתחים.** מפתחות שמוצגים פעם אחת, ו-REST API לשליחה וקריאה.
- **צ'אט תמיכה** עם מנהל המערכת, והתראות בתוך האפליקציה.
- **החשבון שלי.** מכשירים מחוברים עם אפשרות ניתוק, יומן פעילות, החלפת סיסמה ומחיקת חשבון.
- **ממשק.** מצב כהה, מותאם לנייד, ואפשר להתקין כאפליקציה (PWA).

### למנהל

- **סקירה:** משתמשים, שליחות, כשלים, מערכות תקולות, וגרף של 14 ימים.
- **משתמשים:**
  - חיפוש וסינון, אישור, חסימה עם סיבה שמוצגת למשתמש.
  - שינוי חבילה ומכסות, הרשאות אישיות, ניתוק מכשירים, שליחת קוד איפוס.
  - **כניסה לחשבון לצורכי תמיכה.** הכניסה מתועדת ומוצגת למשתמש.
  - הודעה או צ'אט ישיר, ומחיקה.
- **הרשאות וחבילות.** כל פיצ'ר נשלט כך:
  1. **מתג גלובלי.** כבוי = חסום לכולם.
  2. **הגדרה אישית למשתמש.**
  3. **הגדרת החבילה** (חינם, מקצועי, עסקי, או חבילות שתיצור בעצמך).
  4. **ברירת מחדל.**

  בנוסף אפשר להחיל שינוי **על כל החשבונות** או **רק על חשבונות שייפתחו מעכשיו**. זה שימושי כשפיצ'ר הופך לבתשלום והקיימים שומרים עליו.
- **פניות תמיכה, באנרים ושידור התראות** לכל המשתמשים או לחבילה, כולל במייל.
- **יומנים:** ביקורת, שליחות וכשלים, וכל המערכות המחוברות.
- **הגדרות מערכת:** מצב תחזוקה, הרשמה, חבילת ברירת מחדל, התראות כניסה ותדירות בדיקת אוטומציות.
- **הגרסה הישנה:** תצוגה לקריאה בלבד של הקודים והמערכות של V1, כולל כמה כבר יובאו.

## התקנה

דרישות: חשבון Cloudflare, Node.js 18 ומעלה (להרצת הבדיקות: 22.5 ומעלה), וחשבון [Resend](https://resend.com) עם דומיין מאומת.

```bash
git clone <your-repo-url> sms-v2 && cd sms-v2
npm install
npx wrangler login
```

### 1. מסד הנתונים

`wrangler.toml` כבר מצביע על **אותו מסד** של הגרסה הישנה (`sms-db`). יוצרים את טבלאות V2:

```bash
npm run db:migrate
```

הפקודה יוצרת רק טבלאות `v2_*` ורושמת את עצמה ב-`v2_migrations`. הטבלאות הישנות לא משתנות.

### 2. סודות

```bash
npm run secret:key                       # מייצר מפתח הצפנה אקראי — העתק את הפלט
npx wrangler secret put ENCRYPTION_KEY   # הדבק את המפתח
npx wrangler secret put RESEND_API_KEY   # המפתח מ-Resend
```

> ⚠️ **שמור את `ENCRYPTION_KEY` במקום בטוח.** אם הוא יאבד או יוחלף, אי אפשר יהיה לפענח את הטוקנים השמורים, וכל המשתמשים יצטרכו לחבר את המערכות מחדש.

### 3. משתנים ב-`wrangler.toml`

| משתנה | הסבר |
|---|---|
| `APP_URL` | הכתובת הציבורית של האתר. משמשת בקישורים במיילים. |
| `MAIL_FROM` | כתובת השולח. חייבת להיות מדומיין מאומת ב-Resend. |
| `OWNER_EMAIL` | **המייל שלך.** מי שנרשם איתו מקבל הרשאת בעלים. אם ריק, הנרשם הראשון הוא הבעלים. |
| `BASE_PATH` | ריק אם האתר בשורש הדומיין. אם הוא תחת נתיב: `"/sms/v1"` (ראה למטה). |
| `SUBREQUEST_BUDGET` | כמה קריאות חיצוניות מותר ל-Cron בכל ריצה. ראה "תוכנית חינמית" למטה. |

### 4. פריסה

```bash
npm run deploy
```

ואז:

1. היכנס לכתובת והירשם עם `OWNER_EMAIL`. תקבל הרשאת בעלים.
2. ב**ניהול ← הגדרות מערכת** ודא שכל הסודות מסומנים "מוגדר", ושלח מייל בדיקה.
3. ב**ניהול ← סקירה** ודא שה-Cron רץ (מתעדכן כל דקה).

**דומיין מותאם:** בטל את ההערה בשורת `routes` ב-`wrangler.toml`, או חבר דומיין דרך לוח הבקרה של Cloudflare.

### הרצה תחת נתיב (למשל `https://smti.uk/sms/v1`)

אפשר להריץ את V2 בתוך נתיב של דומיין קיים, ליד הגרסה הישנה. צריך להגדיר שלושה דברים, ו**כולם חייבים להתאים**:

1. **Route** ב-Cloudflare ← ה-Worker ← **Settings ← Domains & Routes ← Add ← Route**: `smti.uk/sms/v1*`. חובה עם `*` בסוף, אחרת רק הדף הראשי יגיע ל-Worker, בלי הקבצים וה-API.
2. **`BASE_PATH = "/sms/v1"`** ב-`wrangler.toml`, בלי `/` בסוף.
3. **`APP_URL = "https://smti.uk/sms/v1"`**, כדי שהקישורים במיילים ובקודי האורחים יהיו נכונים.

כשיש גם Route ישן כמו `smti.uk/sms*`, Cloudflare בוחר את ה-Route הספציפי יותר, ולכן `/sms/v1` יגיע ל-V2 וכל השאר ימשיך לגרסה הישנה.

### תוכנית חינמית או בתשלום

ה-Cron רץ כל דקה ומטפל בתור השליחה ובאוטומציות. בתוכנית החינמית של Workers מותרות 50 קריאות חיצוניות לכל הרצה, ולכן `SUBREQUEST_BUDGET=45`. קמפיין גדול יישלח במנות לאורך כמה דקות, ואוטומציות יתחלקו בין הרצות. בתוכנית בתשלום אפשר להעלות ל-400 ומעלה.

## API ציבורי (תקציר)

```bash
curl -X POST https://YOUR-DOMAIN/api/v1/send \
  -H "Authorization: Bearer smt_XXXX" -H "Content-Type: application/json" \
  -d '{"system_id": 1, "phones": ["0501234567"], "message": "שלום!"}'
```

| נתיב | תיאור |
|---|---|
| `POST /api/v1/send` | שליחה, עד 300 נמענים |
| `GET /api/v1/messages?system_id=&phone=&direction=in\|out&since=` | הודעות |
| `GET /api/v1/conversations?system_id=` | שיחות |
| `GET /api/v1/systems` | המערכות בחשבון |

מגבלה: 120 בקשות בדקה לכל מפתח. החסימות, המכסות וההרשאות של החשבון חלות גם על ה-API.

**Webhook:** הכותרת `X-SMT-Signature: sha256=<HMAC של גוף הבקשה>`, עם הסוד שמוצג בעריכת הכלל.

## הנחות לגבי ימות המשיח

- **מפריד נמענים.** ב-`SendSms` כמה נמענים מופרדים בנקודתיים (`:`). אם החשבון שלך מצפה לפסיק, שנה את `PHONE_SEPARATOR` ב-`src/lib/yemot.js`.
- **פורמט תאריכים.** ההנחה היא `YYYY-MM-DD HH:mm:ss` בשעון ישראל, כמו בגרסה הישנה. כך הסמן של האוטומציות משווה תאריכים כמחרוזות.
- **אימות דו-שלבי.** כשהחיבור הוא עם סיסמה, ימות המשיח עשויה לדרוש אימות דו-שלבי. המערכת מזהה זאת ומציגה לבעל המערכת בלבד קישור לאימות. **מומלץ להשתמש בטוקן קבוע (מפתח גישה)**, שלא דורש אימות דו-שלבי ולא פג.

## מעבר מהגרסה הישנה

שתי הגרסאות יכולות לרוץ במקביל לאורך זמן:

1. כל לקוח פותח חשבון ב-V2 עם המייל שלו.
2. ב**מערכות ← ייבוא מהגרסה הישנה** הלקוח מזין את הקוד האישי הישן, וכל המערכות שלו מועתקות ומוצפנות. הייבוא בטוח להרצה חוזרת, ומה שכבר יובא מדולג.
3. המנהל רואה ב**ניהול ← הגרסה הישנה** מי כבר עבר.

כשכולם עברו, אפשר לכבות את ה-Worker הישן. **לא צריך למחוק את הטבלאות שלו.**
